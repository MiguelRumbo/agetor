# Traducción de la UI (español)

Subsistema del fork: `src/mainview/lib/i18n/`. Contrato:

- **Inglés por defecto.** `t("texto en inglés")` devuelve la traducción de `es.ts` si el idioma es `es`, y el mismo texto si no hay entrada. Así los tests unitarios y los e2e, que buscan texto en inglés, no cambian.
- **La clave es el texto inglés exacto.** Si se edita un texto en un componente hay que editar la clave en `es.ts` (si no, esa cadena vuelve a verse en inglés, sin romper nada).
- **Marcadores `{nombre}`**: `t("Hello {name}", { name })`. `index.test.ts` comprueba que cada traducción conserva los mismos marcadores.
- **Idioma en `localStorage`** (`agetor:locale`), leído de forma síncrona al cargar el módulo. Cambiarlo con el selector de **Ajustes → General → Idioma** recarga la página, porque `t()` también se evalúa en constantes de módulo.
- **Columnas del tablero**: `tColumn(label)` con `esColumns` (aparte porque "Review" también es un verbo en otros sitios).
- **Modos y esfuerzos** de `AGENT_OPTIONS` se traducen al mostrarlos (`t(m.label)`); los `id` no se tocan. Los `hint` largos siguen en inglés.
- Si un archivo ya tiene una variable local `t` (p. ej. `(t) => t.id`), se importa como `import { t as tr }` y se llama `tr("…")`: `App.tsx`, `SettingsDialog.tsx`, `TerminalView.tsx`.

## Cómo añadir una cadena

1. Envolver el texto en el componente con `t("…")`.
2. Añadir `"…": "…"` a `es.ts`.
3. `bun test src/mainview/lib/i18n`.

## Qué queda en inglés (pendiente)

- Textos del core que llegan a la UI (`src/bun/`: errores de `server.ts`, líneas de estado del transcript, pistas de `agent-status.ts`): el core no conoce el idioma de la UI.
- CLI y TUI (`src/cli/`).
- Frases con estructura variable dentro de componentes (ternarias, plantillas con `${}`) que el volcado automático no capturó, y los `hint` de modos y esfuerzos.
- Documentación (`README.md`, `docs/architecture/`).
- Prompts que recibe el agente: se dejan en inglés a propósito (ver `traduccion-inventario.md`).
